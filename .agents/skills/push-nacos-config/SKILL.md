# 推送配置到 Nacos

将本仓库内的配置文件推送到 Nacos：公有配置来自 middleware/nacos/config/*.yml，dataId 为文件名；各服务私有配置来自 *
/src/main/resources/application-spring.yml，dataId 从同级 application.yml 的 spring.application.name 解析为 服务名.yml。

---

## 一、前置条件

启动任务前必须确定以下信息；缺失或无法从上下文推断时，先询问用户补齐：

| 条件         | 说明                   | 默认值                                      |
|--------------|------------------------|---------------------------------------------|
| Nacos 地址   | 服务端地址             | http://127.0.0.1:8848                       |
| 账号 / 密码  | 登录凭证               | nacos / nacos                               |
| 命名空间 ID  | 目标命名空间           | dev                                         |
| 分组         | 目标分组               | DEFAULT_GROUP                               |
| 仓库根目录   | 定位配置文件的绝对路径 | 从上下文推断，即当前工作区                  |
| 公有配置来源 | 待扫描位置             | middleware/nacos/config/*.yml               |
| 私有配置来源 | 待扫描位置             | */src/main/resources/application-spring.yml |

所有参数均可被用户在确认环节覆盖，以用户最终确认为准。

---

## 二、执行流程

任务按以下阶段顺序推进，不得跳过或重排；前一阶段未完成或失败，不得进入下一阶段：

| 阶段              | 目标                      | 进入下一阶段的条件                |
|-------------------|---------------------------|-----------------------------------|
| 1. 连接验证与登录 | 验证 Nacos 可达并完成登录 | 取得有效 token 且命名空间核验通过 |
| 2. 扫描与生成清单 | 按映射规则扫描仓库        | 清单生成完毕，冲突已标记          |
| 3. 用户确认       | 展示清单与目标参数        | 用户明确确认推送                  |
| 4. 执行推送       | 逐个推送并校验结果        | 全部成功，或失败终止              |
| 5. 回读校验       | 比对本地与 Nacos 内容一致 | 逐项校验完成                      |

各阶段要点：

- **阶段 1**：登录取得 accessToken 后，调用命名空间检查接口核验目标命名空间存在（data 为
  1）；不存在则询问用户是否创建，用户同意后调用创建命名空间接口（成功则继续），否则停止任务
- **阶段 2**：扫描公有与私有配置来源，解析每个私有配置的 spring.application.name 生成
  dataId；无法解析的标记为需用户手动指定；同名重复的标记为冲突待用户决策
- **阶段 3**：展示完整清单（dataId 与文件对应关系）及目标地址、命名空间、分组；提醒已存在配置将被覆盖、配置可能含密码等敏感信息
- **阶段 4**：逐个发布配置，带 Bearer token，type 为 yaml，实时反馈进度；每个响应校验 code 为 0
- **阶段 5**：回读比对本地与 Nacos 的 md5，仅报告一致、不一致或不存在，不触发任何自动操作

流转规则：

- 阶段 3 用户修改参数或增删文件，则重新展示清单再次确认；选择取消，则终止任务
- 阶段 4 任一推送失败，立即停止并输出完整响应，不回滚已成功项；Nacos 不可达、登录失败等场景直接报告，不重试
- 阶段 4 全部成功后进入阶段 5 回读校验

## 三、接口范围

仅允许以下接口；禁止 v1/v2 配置接口，如 /nacos/v1/cs/configs、/nacos/v2/cs/config，Nacos 3.2 起已移除：

| 用途         | 方法与路径                               |
|--------------|------------------------------------------|
| 登录         | POST /nacos/v1/auth/login                |
| 发布配置     | POST /nacos/v3/admin/cs/config           |
| 检查命名空间 | GET /nacos/v3/admin/core/namespace/check |
| 创建命名空间 | POST /nacos/v3/admin/core/namespace      |
| 获取配置     | GET /nacos/v3/admin/cs/config            |

---

## 四、核心约束

**行为约束**

- 确认前置：发布接口只能在阶段 3 用户明确确认推送后调用；此前仅可执行登录、命名空间检查等查询类接口，创建命名空间须先获用户明确同意
- 用户参数优先：确认环节修改的参数覆盖所有默认值
- 只读原则：仅读取源文件内容，不修改仓库内任何文件
- 单次登录：登录一次复用 token，不做过期续期处理

**数据与安全约束**

- 源文件须为 UTF-8；type 恒为 yaml
- 私有配置必须能解析 spring.application.name，否则跳过该项并提示用户手动指定 dataId
- 阶段 3 必须提醒：配置可能含数据库密码等敏感信息，推送前由用户自行检查
- 默认参数面向本地开发环境；用户自定义地址须为 http 或 https 开头，并包含主机与端口
