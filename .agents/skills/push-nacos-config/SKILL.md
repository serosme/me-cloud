# 推送配置到 Nacos

将本仓库内的配置文件推送到 Nacos：公有配置来自 middleware/nacos/config/*.yml，dataId 为文件名；各服务私有配置来自 *
/src/main/resources/application-spring.yml，dataId 从同级 application.yml 的 spring.application.name 解析为 服务名.yml。

---

## 一、前置条件

启动任务前必须确定以下信息；缺失或无法从上下文推断时，先询问用户补齐：

| 条件         | 说明                   | 默认值                                      |
|--------------|------------------------|---------------------------------------------|
| Nacos 地址   | 服务端地址             | http://127.0.0.1:8848                       |
| 账号 / 密码  | 登录凭证               | nacos / nacos                               |
| 命名空间 ID  | 目标命名空间           | dev                                         |
| 分组         | 目标分组               | DEFAULT_GROUP                               |
| 仓库根目录   | 定位配置文件的绝对路径 | 从上下文推断，即当前工作区                  |
| 公有配置来源 | 待扫描位置             | middleware/nacos/config/*.yml               |
| 私有配置来源 | 待扫描位置             | */src/main/resources/application-spring.yml |

所有参数均可被用户在确认环节覆盖，以用户最终确认为准。

---

## 二、执行框架

任务必须按以下阶段顺序推进，不得跳过、合并或重排序；前一阶段未完成或失败，不得进入下一阶段：

| 阶段              | 目标                                      | 进入下一阶段的条件       |
|-------------------|-------------------------------------------|--------------------------|
| 1. 连接验证与登录 | 验证 Nacos 可达并完成登录，取得 token     | 获取到有效 token         |
| 2. 扫描与生成清单 | 按映射规则扫描仓库，生成待推送清单        | 清单生成完毕，冲突已标记 |
| 3. 用户确认       | 展示清单与目标参数，等待用户决策          | 用户明确确认推送         |
| 4. 执行推送       | 逐个推送并校验结果                        | 全部成功，或失败终止     |
| 5. 回读校验       | 回读已推送配置，比对本地与 Nacos 内容一致 | 逐项校验完成             |

流转规则：

- 阶段 3 用户选择修改参数或增删文件，则重新展示清单再次确认；选择取消，则终止任务
- 阶段 4 任一推送失败，立即停止，不回滚已成功的推送
- 阶段 4 全部成功后进入阶段 5 回读校验

---

## 三、任务清单

执行各阶段时对照核对，确保关键动作不遗漏：

**阶段 1，连接验证与登录**

- [ ] 地址格式有效，为 http 或 https 开头并包含主机与端口，Nacos 可达
- [ ] 登录响应包含 accessToken，已提取保存

**阶段 2，扫描与生成清单**

- [ ] 已扫描公有与私有配置来源
- [ ] 每个私有配置已从同级 application.yml 解析出 spring.application.name；无法解析的标记为需用户手动指定 dataId
- [ ] 清单每项含 dataId、源文件路径、类型，类型为公有或私有
- [ ] 已检查 dataId 冲突，即同名重复，冲突已标记待用户决策

**阶段 3，用户确认**

- [ ] 已展示完整清单，即 dataId 与文件的对应关系，以及目标地址、命名空间、分组
- [ ] 已提醒覆盖策略，即已存在配置将被覆盖，以及敏感信息风险，即配置可能含密码或密钥
- [ ] 已获得用户明确指令；仅用户确认推送后可进入阶段 4

**阶段 4，执行推送**

- [ ] 逐个推送，使用 v3 Admin API，带 Authorization Bearer token，type 为 yaml，实时反馈进度
- [ ] 每个响应校验 code 为 0；失败立即停止并输出完整响应
- [ ] 全部成功后进入阶段 5 回读校验

**阶段 5，回读校验**

- [ ] 通过 GET /nacos/v3/client/cs/config 回读，比对本地与 Nacos 的 md5
- [ ] 仅报告结果，即一致或不一致或不存在，不触发任何自动操作

---

## 四、核心约束

**接口范围**：仅允许以下接口；禁止 v1/v2 配置接口，如 /nacos/v1/cs/configs、/nacos/v2/cs/config，Nacos 3.2 起已移除

| 用途         | 方法与路径                              | 说明                                                                                  |
|--------------|-----------------------------------------|---------------------------------------------------------------------------------------|
| 登录         | POST /nacos/v1/auth/login               | 表单参数 username 与 password，响应中提取 accessToken                                 |
| 发布配置     | POST /nacos/v3/admin/cs/config          | 表单参数 namespaceId、groupName、dataId、content、type；需 Authorization Bearer token |
| 命名空间列表 | GET /nacos/v3/admin/core/namespace/list | 校验命名空间存在                                                                      |
| 获取配置     | GET /nacos/v3/client/cs/config          | 回读校验用                                                                            |

**行为约束**

- 确认前置：发布接口只能在阶段 3 用户明确确认推送后调用；此前仅可执行登录、命名空间列表等查询类接口
- 失败即停：任一推送返回 code 非 0，立即停止并输出完整响应，不回滚已成功项；Nacos 不可达、登录失败、命名空间不存在等场景直接报告，不重试
- 用户参数优先：确认环节修改的参数覆盖所有默认值
- 只读原则：仅读取源文件内容，不修改仓库内任何文件
- 单次登录：登录一次复用 token，不做过期续期处理

**数据与安全约束**

- 源文件须为 UTF-8；type 恒为 yaml
- 私有配置必须能解析 spring.application.name，否则跳过该项并提示用户手动指定 dataId
- 阶段 3 必须提醒：配置可能含数据库密码等敏感信息，推送前由用户自行检查
- 默认参数面向本地开发环境；用户自定义地址须为 http 或 https 开头，并包含主机与端口
